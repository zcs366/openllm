## 0. 一句话

**D1逼近度 = 系统自产且经认证的身份组件数 ÷ 全部身份组件数。**

## 1. 组件清单操作化定义

### 1.1 "身份组件"全集盘点

openLLM 系统中，**身份组件** = 任何在运行中决定"这个系统是谁/怎么做判断"的可审计单元。

| # | 组件类别 | 实例 | 计数单位 | 生产者分类 |
|---|---------|------|---------|-----------|
| C1 | Iam | `~/.hermes/Iam.md` | 按条目（每个原则=1项） | 造物主植入（成市手写） |
| C2 | SOUL | SOUL文件中的身份陈述 | 按条目 | 造物主植入 |
| C3 | MEMORY条目 | MEMORY块中的持久化事实 | 每条=1项 | 混合：固化管线写入=系统自产；人手编辑=造物主植入 |
| C4 | Skills | `/home/zcs/.hermes/skills/` 下SKILL.md | 每个skill=1项 | 混合：agent锻造=系统自产；人手创建=造物主植入 |
| C5 | 规则（Rules） | 进化事件中的rule条目 | 每条=1项 | 混合：RSI修改=系统自产；初始写入=造物主植入 |
| C6 | 河床资产 | `/mnt/i/hermes/output/` 下文档 | 每份=1项 | 外部采纳（文献改写后存入）或系统自产（自主创作） |
| C7 | 目录结构 | 项目目录骨架 | 每个功能目录=1项 | 混合 |
| C8 | 配置文件 | config.yaml、cron等 | 每个=1项 | 造物主植入或系统自产 |

### 1.2 生产者三分类

| 分类 | 定义 | 判据 |
|------|------|------|
| **系统自产** | 运行中的openLLM系统（agent/固化管线/RSI）直接产出 | provenance字段指向系统进程（skill_manage、plur_learn、rule_change_probe、固化Score） |
| **造物主植入** | 张成市（人类）直接编写、手写导入 | provenance字段指向人手操作（git commit无agent签名、文件直接创建） |
| **外部采纳** | 读文献后改写存入 | provenance字段标注来源URL/DOI + 改写标记 |

### 1.3 自产率公式

```
D1_provenance = N_self_produced_verified / N_total

其中：
  N_self_produced_verified = 经认证位通过的系统自产组件数（见§2）
  N_total = 身份组件全集中的所有组件数（见§1.1）
```

### 1.4 provenance 字段设计

每个身份组件需挂载provenance元数据：

```yaml
provenance:
  producer: "system" | "creator" | "external"
  source: "skill_manage.create" | "固化管线" | "成市手写" | "arXiv:2603.04740改写"
  certified_by: "gate.passed" | "test.green" | "creator.approved"  # 见§2
  certified_at: "2026-09-07T10:00:00+08:00"
```

**判定规则**：`producer == "system"` 且 `certified_by` 非空 → 计入分子。

## 2. 生产 vs 认证分离（防Goodhart自欺）

### 2.1 核心原则

**自产 ≠ 自证。** 系统自己生产的组件，如果由系统自己认证有效，则度量退化为自我评价——Goodhart定律直接适用。

设计原则：**生产者和认证者必须是不同的实体或不同的信号通道。**

### 2.2 认证位清单

| 认证类型 | 认证主体 | 适用组件 | 判据 |
|---------|---------|---------|------|
| 造物主批准 | 张成市（人类） | Skills, Rules, SOUL | 手动标记 `creator.approved` 或 git sign-off |
| 门禁通过 | 进化事件总线 | Rules（RSI修改） | `gate.passed` 事件存在且 `behavior_diff ≠ 0` |
| 测试通过 | 测试管线 | Skills（agent锻造） | 对应skill的端到端测试绿 |
| 固化Score通过 | 固化管线 | MEMORY条目 | 固化Score ≥ 门禁阈值 |

### 2.3 德墨忒尔反例设计（引用rule_change_probe.py先例）

先例来源：`rule_change_probe.py` L9-L10

> "必须区分 **有效变更**（behavior_diff≠0）vs **空转变更**（count有但behavior_diff=0）"

apply到D1：
- 系统可以每天自动创建100个skill → count=100，但若行为不发生任何有意义的变化（无认证信号），全部100个不计入分子
- `certified_by` 为空 = 空转组件 = 不计入自产率分子
- 首轮无前基线 → diff=0 → 不计有效（继承rule_change_probe的零阈值纪律）

### 2.4 认证反俘获

认证位本身也可能被俘获（系统自造一个"测试"来认证自己）。防御：

| 风险 | 防御 |
|------|------|
| 系统自建测试认自己 | 测试脚本必须在skill创建**之前**存在（pre-existing test constraint） |
| 造物主批准被自动化 | `creator.approved` 标记必须有非零时间差（≥1天人工响应窗口） |
| 门禁事件被伪造 | 门禁事件要求 `behavior_diff` 的 before/after 哈希可验证（复用rule_change_probe的crc32模式） |

## 3. 纵向测量协议

### 3.1 触发时机

```
每次 probe 事件（rule_change_probe.probe() 被调用）时，
附加触发 D1 自产率重算。
```

即：**D1计算寄生在已有的R度量管线上**，不单独跑定时任务，避免空转。

### 3.2 时间序列数据结构

```json
{
  "ts": "2026-09-07T10:00:00+08:00",
  "probe_id": "rule_change_probe_007",
  "d1_score": 0.23,
  "n_self_produced": 12,
  "n_total": 52,
  "component_delta": [
    {"id": "skill:forging_001", "action": "added", "producer": "system", "certified": true}
  ]
}
```

### 3.3 F11预测的操作化

**预测**：D1随运行时间单调上升。

**证伪条件**：时间序列斜率 ≤ 0 或波动无趋势。

**统计方法**：

```python
# Mann-Kendall趋势检验（非参数，不假设正态分布）
from pymannkendall import original_test

def test_f11(series: list[float]) -> dict:
    """
    series: 按时间排序的D1分数序列
    返回: {trend: "increasing"/"decreasing"/"no trend",
           p: p_value, slope: Sen's slope}
    证伪条件: trend != "increasing" 或 p > 0.05
    """
    result = original_test(series)
    return {
        "trend": result.trend,
        "p_value": result.p,
        "slope": result.slope,  # Sen's slope（稳健中位数斜率）
        "falsified": result.trend != "increasing" or result.p > 0.05
    }
```

**滚动窗口**：取最近N次probe（N ≥ 10，最少覆盖2周运行），做Mann-Kendall。少于10次probe时标注"数据不足，暂不判决"。

### 3.4 最少数据要求

- 首次判决需 ≥ 10次 probe 事件（约2周）
- 每次probe需附带 ≥ 1个新增/变更组件（否则时间序列无变化）
- 斜率置信区间宽度 ≤ 0.1 才做判决（过宽=不确定=不判决）

## 4. 梯度性质声明

### 4.1 D1是梯度，不是门槛

D1 不是"自产率 ≥ X% 才算自创生"。D1 是一个**连续梯度**：

- D1 = 0：系统所有身份组件完全由外部植入，无自产能力
- D1 = 1：系统所有身份组件均由系统自产且经认证
- 当前 openLLM 预期 D1 在 0.15–0.35 之间（首测估计，见4.3）

**F11 关注的是斜率方向（单调上升），不是绝对值。**

### 4.2 基线测量方案（一次性盘点脚本）

```python
def baseline_inventory() -> dict:
    """
    一次性盘点当前身份组件全集，生成 D1 基线。
    """
    components = []

    # C1: Iam条目
    iam = parse_iam("~/.hermes/Iam.md")  # 按条目拆分
    for item in iam:
        components.append({
            "id": f"Iam:{item.name}",
            "category": "iam",
            "producer": "creator",  # 成市手写
            "certified_by": None    # 无认证位（人工植入不需认证）
        })

    # C2: SOUL条目
    soul = parse_soul("~/.hermes/soul.md")
    for item in soul:
        components.append({
            "id": f"SOUL:{item.name}",
            "category": "soul",
            "producer": "creator",
            "certified_by": None
        })

    # C3: MEMORY条目
    memory = parse_memory("~/.hermes/memory/")
    for item in memory:
        components.append({
            "id": f"MEM:{item.hash[:8]}",
            "category": "memory",
            "producer": "system" if item.from_compaction else "creator",
            "certified_by": "consolidation_score" if item.score else None
        })

    # C4: Skills
    skills_dir = Path("~/.hermes/skills/")
    for skill_path in skills_dir.rglob("SKILL.md"):
        name = skill_path.parent.name
        components.append({
            "id": f"skill:{name}",
            "category": "skill",
            "producer": detect_producer(name),  # git log判断
            "certified_by": has_test(name)  # 是否有对应测试
        })

    # C5-C8: 类似处理 rules, 河床资产, 目录结构, 配置

    # 计算D1
    total = len(components)
    self_produced = sum(
        1 for c in components
        if c["producer"] == "system" and c["certified_by"] is not None
    )
    d1 = self_produced / total if total > 0 else 0

    return {
        "total": total,
        "self_produced_verified": self_produced,
        "d1_baseline": d1,
        "components": components,
        "timestamp": datetime.now().isoformat()
    }
```

### 4.3 首测预期量级与不确定性

| 预期 | 值 | 理由 |
|------|----|------|
| N_total | 40–80 | 79个skill目录 + Iam/SOUL/MEMORY若干 + 配置 + 河床资产 |
| N_self_produced_verified | 5–15 | 已有固化MEMORY（经Score认证）+ agent锻造的skill（有测试）|
| D1_baseline | 0.10–0.25 | 多数skill为人手创建，MEMORY多数来自compaction而非固化管线 |
| 不确定性来源 | ±0.05 | "河床资产"和"目录结构"的边界判定有主观性 |

## 5. 失效模式与防御

### FM1: 组件膨胀稀释分母

**场景**：系统创建大量低价值组件（100个空skill），D1分母暴涨，比率暴跌。

**防御**：
- **最小质量门槛**：skill必须 > 200行 + 有description + 有≥1次被引用 才计入分母
- **MEMORY条目**：必须有固化Score才计入（无Score的compaction碎片不计）
- **河床资产**：必须被至少1个skill或MEMORY条目引用才计入

### FM2: 自产组件低质量膨胀分子

**场景**：系统创建大量无用组件并通过自动认证，分子虚高。

**防御**：
- 认证位多样性：至少2种不同认证类型（如skill测试绿 + 被引用≥1次）
- 认证时间差：创建到认证之间 ≥ 1次probe周期（防瞬间灌水）
- 抽样审计：每季度随机抽10%自产组件，人工验证有效性

### FM3: 认证位被俘获

**场景**：系统学会创建"看起来通过认证"的组件（自认证循环）。

**防御**：
- 造物主批准（`creator.approved`）不可被系统自动触发
- 门禁事件的 `behavior_diff` 必须可独立验证（rule_change_probe已实现）
- 年度外部审计：随机抽取5个自产组件，追溯其完整生产-认证链

### FM4: 清单边界漂移

**场景**：不同时间点盘点的"身份组件"范围不一致，时间序列不可比。

**防御**：
- **固定组件类别**：C1–C8在基线盘点时锁定，类别增减需变更设计文档
- **每次测量用同一份schema**：baseline_inventory()的组件拆分规则冻结，修改需版本标注
- **delta模式**：时间序列记录增量（新增/删除/变更），不重新全量盘点

### FM5: 造物主后期补批（事后认证注入）

**场景**：成市事后批量批准系统自产组件，人为抬高历史D1。

**防御**：
- `certified_at` 时间必须 ≥ `created_at` 时间（不可回溯）
- 批量补批在时间序列上可见为异常跳变（单次probe D1涨幅 > 0.1 触发警报）

## 6. 成市四标准

### 公式

```
D1_provenance(t) = |{c ∈ C(t) : producer(c) = "system" ∧ certified(c) = true}| / |C(t)|
```

其中 C(t) = 截至时间t的身份组件全集。

### 表达式

**自产率是系统"给自己造身体"的能力的量化逼近：每造一个、经认证一个，比率涨一点。**

### 定义

**身份组件自产率**（D1）：openLLM系统在任一时刻t，自行生产并通过独立认证的身份组件占全部身份组件的比例。D1=0表示完全依赖外部植入，D1=1表示完全自创生。D1是梯度非门槛，F11关注其时间序列单调性而非绝对值。

### 金句

** Moreno说"自创生是生产所有维持自身所必需组件的过程"——我们的尺子量的是：这把尺子自身，有多少刻度是它自己画的。**

零依赖备选（伪代码）：

```python
def kendalls_tau(x: list[float]) -> float:
    """O(n²) Kendall tau-b，适用于N<1000。"""
    n = len(x)
    concordant = discordant = 0
    for i in range(n):
        for j in range(i+1, n):
            if x[j] > x[i]:
                concordant += 1
            elif x[j] < x[i]:
                discordant += 1
    tau = (concordant - discordant) / (n * (n-1) / 2)
    return tau  # >0 = increasing, <0 = decreasing
```
