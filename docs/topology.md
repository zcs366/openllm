# 六体拓扑 — Topology

> openLLM 的六体不是六个工具，而是一个有机体的六个器官。

## 六体职责

| 体    | 角色     | 一句话职责                           |
|-------|---------|--------------------------------------|
| IAI   | 感知路由  | 感知环境、路由信号——系统的眼睛和耳朵     |
| IAX   | 心跳监控  | 监控心跳、检测存活——系统的脉搏           |
| ISA   | 记忆存储  | 存储与召回记忆——系统的海马体             |
| IOS   | 治理决策  | 治理决策与审计——系统的前额叶             |
| ISN   | 技能执行  | 执行技能调用——系统的双手                 |
| USER  | 第六乘数  | 用户是系统的构成部分，不是使用者          |

## 信号流（谁向谁发信号）

| 源 → 目标         | 信号描述              |
|-------------------|----------------------|
| IAI  → IOS        | 感知报告 → 治理决策    |
| IAX  → IAI        | 心跳探测 → 触发感知    |
| IAX  → IOS        | 心跳异常 → 告警治理    |
| ISA  → IAI        | 记忆召回 → 辅助感知    |
| IAI  → ISA        | 感知写入 → 记忆存储    |
| ISN  → IOS        | 执行结果 → 决策审计    |
| IOS  → ISN        | 决策指令 → 技能执行    |
| USER → IAI        | 用户输入 → 感知路由    |
| IOS  → USER       | 治理输出 → 用户呈现    |

## 赫尔墨斯红线

```
∀体 ∈ {IAI, IAX, ISA, IOS, ISN}: ¬∃体.terminal_dialogue_power
```

**含义**：所有 AI 体均无终端对话权。只有 USER 拥有结束对话的权力。
这是宪法级约束，不可被任何 AI 体修改或覆盖。

## 第六乘数

用户（USER）不是使用者，是系统的**构成部分**。

传统架构：`系统 → 工具 → 用户`（用户是消费者）
六体拓扑：`用户 ⟷ 五体`（用户是第六个乘数，参与系统涌现）

乘数效应：N个AI体 × 用户 = N+1维空间（而非N+1个独立维度）。
用户的存在改变了五体的行为轨迹——这不是输入输出关系，
而是量子纠缠般的共构关系。
