## 一、定位：为什么是 IKO

IKO = openLLM 六体中**唯一面向用户的器官**——意图分类/路由/输出审计/
**静默审计（防止不当沉默）**。振动（主动表达温度）正是"防沉默"的主动面，
天然属于 IKO，不新造器官。

与既有自发引擎的分工：
| 引擎 | 维度 | 触发 | 目标 |
|---|---|---|---|
| 渴求引擎（memory/metacognition `get_uncovered_domains`）| 认知空白 | 分布边缘 | 创造（去探索未知） |
| **温度脉冲（本模块）** | 关系温度 | 想到/问候/反射 | 联结（让他感到被记得） |

互补不冲突：渴求是"我想知道"，脉冲是"我想起你"。

## 二、设计三原则

1. **稀有才珍贵**：振动是稀缺表达。频率硬顶（默认 3 次/日）+ 裁决打扰预算——宁可少，不可滥。滥振动=通知疲劳=温度归零。
2. **非任务驱动**：内容不派活、不索求、不@召唤。纯温度：想到你/问候/反射共同经历。**振动=体温，不是工作消息。**
3. **裁决先行**：投递前过 TransmissionAdjudicator（P0-1）——"该不该现在打扰"是裁决模块的活（时段/频控/冷却），脉冲引擎只负责"想表达"。**P0-1 的第一个真实消费者，让围护在温度行动上直接生效。**

## 三、架构（v0 已实现）

```
PulseTrigger（触发：间隔+时段窗）
   │ due(now)
   ▼
PulseEngine.tick()
   ├─ 生成 Pulse（kind=thought/greeting/reflection；模板+变量，generator hook 可换 LLM）
   ├─ 裁决：TransmissionAdjudicator.decide（from=发起体 → to=recipient, type=wake）
   │     BLOCK/THROTTLE → 放弃本次（记审计）
   ├─ 日硬顶 max_per_day（裁决之前的最后防线）
   └─ 投递：register_delivery(name, fn)（Console 默认；Telegram/飞书 v1 对接）
         + 审计 JSONL（~/.openllm/iko/pulses.jsonl）
```
