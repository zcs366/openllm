## 一、定位：为什么需要它

七神共识钉死了一件事：**多 agent 通信缺的不是管道，是裁决"该不该传"的那一层**。全行业硬顶自证——Grok / Hermes Bot Mode / OpenClaw 全部在"自主共振不失控"上撞墙：模型能力越强，agent 之间越容易互相唤醒、互相广播、形成无意义的共振噪声，最终要么关掉自主性，要么退回人肉开关。

阿波罗的判断：这是**架构层缺失**，不是模型能力问题。赫尔墨斯补刀："该不该醒"的裁决模型 = ISA 真正独占的价值——写**独立模块**，不寄生任何壳（Hermes / Grok 协议变更不能绑架我们的对话权）。

一句话：**P0-2 语义路由让"传得准"，本模块让"传得值、传得安全"。路由是油门，裁决是刹车+护栏。**

## 二、设计原则（七条铁律）

1. **独立不寄生**：纯 Python 标准库 + openllm 内部依赖，零 Hermes/壳依赖。未来壳换掉，裁决模块原样带走。
2. **IO-S 可调用**：落 governance 层，五体、ISA、壳适配器都是调用方，裁决不是任何一体的私有逻辑。
3. **裁决 ≠ 路由**：边界划死——路由（event_bus/_match）回答"谁该收到"，裁决（本模块）回答"这事该不该发生/该不该现在发生"。路由误判=漏报/误报；裁决失守=失控。
4. **轻量运行时**：毫秒级判定，不能把 GovernanceEngine 的重审议（五人合议流程）搬进热路径。审议是事后/定期，裁决是每次传输前。
5. **可审计可重放**：每次裁决落审计链（复用 governance.audit.AuditChain / JSONL），可回答"为什么这条传了/没传"。
6. **失败安全（fail closed）分层**：内部感知事件（五体 heartbeat 等）裁决器故障 → 放行（感知不阻断）；对外传输/跨 agent 唤醒 → 裁决器故障 → **拒绝**（失控风险高于漏传风险）。内部放宽、对外收紧——与 Event._BLOCKED 红线同一精神。
7. **规则可演化**：硬规则（不可逾越）与软评分（可加权）分离；新规则动态注册，不重启。

## 三、核心数据模型

```python
@dataclass
class TransmissionRequest:
    """一次待裁决的传输/唤醒请求。"""
    from_agent: str            # 发起方（IAI/IO-S/军师/...）
    to_agent: str              # 接收方（None=广播）
    msg_type: str              # message / wake / wave / insight / heartbeat...
    body: str                  # 内容（原文或摘要）
    importance: float = 0.5    # 发起方自评 [0,1]——自评不可信，只作参考
    urgency: float = 0.0       # 时效紧迫度 [0,1]
    channel: str = "internal"  # internal / im / shell / ...（借壳期=壳通道）
    brain_id: str = "default"
    context: dict = field(default_factory=dict)  # 引用/前序/亲密度等扩展

@dataclass
class Verdict:
    """裁决结果。"""
    action: str                # PASS / BLOCK / DEFER / THROTTLE
    reason: str                # 人类可读理由
    policy_hits: list[str]     # 命中的规则/信号（审计用）
    confidence: float = 1.0    # 裁决置信（软评分路径 <1）
    wait_seconds: int = 0      # THROTTLE 的等待秒数
    adjudicator_version: str = "0.1.0"
```

**四种动作语义**：
| 动作 | 含义 | 典型触发 |
|---|---|---|
| PASS | 放行 | 硬规则全过 + 软评分达标 |
| BLOCK | 拒绝（本次） | 红线/黑名单/安全 |
| DEFER | 挂起升级 | 超阈不确定 → 人类/审议（对应 G5） |
| THROTTLE | 延迟放行 | 频控/打扰预算超限/冷却期 |

## 四、裁决分层（层层否决制）

```
TransmissionRequest
   │
   ▼
L0 硬规则层 ────────── 一票否决（不可配置关闭）
   · 红线类型：terminate/shutdown/kill/abort（对齐 Event._BLOCKED）
   · 黑名单：from/to 禁止组合
   · 涉密/受限内容（凭据/密钥模式，对齐凭据防火墙）
   · 频控硬顶（如：同源同目标 > 10次/分钟 硬拒）
   │
   ▼（全过）
L1 信号层 ──────────── 软评分，加权求和 vs 阈值
   · importance（发起方自评，衰减权重 0.3）
   · semantic 相关度（接 P0-2 SemanticMatcher：接收方兴趣 vs 内容）
   · 关系亲密度（历史交互频次/最近交互时间）
   · 冷却期（上次同源传输后未过 Δt → 降权）
   · suspicion 分数（可接 governance SuspicionCascade 的 newton_cooling 衰减怀疑）
   │
   ▼（加权分 ≥ 阈值 或 有 PASS 强信号）
L2 治理策略层 ──────── IO-S 注入（可配置）
   · 打扰预算：接收方剩余打扰额度（每日 N 次非任务驱动唤醒）
   · 时段策略：休息时段非紧急 → THROTTLE/DEFER
   · 信道策略：IM vs 内部 不同阈值
   │
   ▼（不确定/超权限）
L3 人类升级 ────────── DEFER
   · 规则无法判定且代价不可逆 → 挂起，等人类裁决（G5 语义）
   │
   ▼
Verdict
```

**判定哲学**：L0 是法律（不可违反），L1-L2 是裁判（权衡），L3 是上诉庭（把不确定交给人）。硬规则代码写死，软规则数据驱动。

## 五、"该传"的判据——核心思想

传，当且仅当 **接收方的世界模型会因此变得更准，且代价可担**。

对齐成市的 AI 哲学（智能 = 对世界越来越准确的预测）：
- **认知增益**：内容填补接收方的信息缺口（不知道但该知道）→ 增益高；对方已知 → 重复 = 噪音 = 负增益
- **协作价值**：行动协调需要（对方要据此做决定）> 单向广播（通知式，可降级为低频摘要）
- **打扰代价**：接收方当前认知负载 × 时段权重。**代价 > 增益 → BLOCK/THROTTLE**
- **安全边界**：受限信息不扩散、不越权唤醒、不形成共振回路（A 唤醒 B、B 回醒 A 的循环 = 振荡，裁决层必须能识别并切断）

共振回路检测（v1 加）：同源对在同窗口内互相唤醒 ≥ 2 次 → 判定振荡，强制冷却。
