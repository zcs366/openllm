## 四、还剩下的问题（如实记，没修）

1. **胶囊分层碎片**（P2）：`memory_write` 的洞察写进"当前最新胶囊"，而 `sleep()` 另写一个 `s{ts}` 胶囊。唤醒只念最新的那一个，长期记忆会被分摊到多个文件，靠 mtime 抽签决定谁被念出来。真正的解法是"一个会话一个胶囊，工具写入同一会话"，涉及会话标识的贯通，不是一行能改的。
2. **唤醒内容有噪声**（P2）：`wake()` 把上一轮的"模型最后回应"也当洞察念出来（见腿3 重启后那段），读起来像走错房间。洞察该有类型标签（用户事实 / 会话摘要 / 回执），现在是混着塞。
3. **首次 `sleep()` 慢**（P3）：会加载 embedding 权重（`Loading weights: 100%|103/103`），几秒级。
4. **全量 pytest 仍跑不完**（P1 工程债）：>420s 超时，没有可用的全量基线，只能靠定向子集。
5. **config.json 明文 API key**（安全债）：启动审计自己就告警了（"以下provider有明文API key: deepseek, mimo, lmstudio"）。审计看见了，但没人管。
6. **测试卫生**（已修，记一笔）：引擎的 MemoryOS 默认落在 `~/.openllm/output/memory`，**不沙箱 HOME 的测试会污染并读到用户真实记忆库**——首轮测试就中招了，已加沙箱并清掉污染（备份在 `/tmp/openllm_memory_backup_20260910/`）。

## 五、下一步建议

1. **会话标识贯通**（解 P2-1/P2-2）：engine 启动时定一个 session_id，chat 写入、工具写入、sleep 写入都用它——记忆不再碎片化，唤醒念的也干净。
2. **洞察分型**：`insights` 从 `list[str]` 升级为带 type 的条目，唤醒只念"用户事实"和"未完成事项"。
3. **建可跑的全量基线**：给慢测试打标记（`-m slow`），日常跑快集，夜间跑全量。
4. **key 挪出配置文件**：审计已经指出了，改成环境变量引用即可。
