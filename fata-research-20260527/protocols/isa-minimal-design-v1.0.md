# Isa 最小可用设计 v1.0

> 不能仰望于人。
> 国内 Telegram 用不起来。
> Isa 是 openLLM 的肉身。

---

## 一、定位

| 不是 | 而是 |
|------|------|
| 又一个聊天 App | openLLM 的唯一栖身之所 |
| Telegram 的替代品 | 一个眼神一个念头就是指令的入口 |
| 微信/元宝的竞品 | AI 原生的频道客户端 |

**Isa 的本质：iPhone 式的设计——一块玻璃变成一切。**

---

## 二、核心功能（最小可用版）

### 必须有（Day 1）

| 功能 | 说明 | 为什么必须 |
|------|------|-----------|
| **DM 聊天** | 1对1，用户 ↔ Agent | 基础交互 |
| **群组** | 多人 + Agent 共处 | 社交性 |
| **分身管理** | 一个 SOUL 多个实例 | 频道共振的基础 |
| **国内可用** | 不依赖代理，服务器在国内 | 核心需求 |

### 应该有（Day 7）

| 功能 | 说明 | 为什么应该 |
|------|------|-----------|
| **状态可见** | Agent 当前在想什么/做什么 | 信任感 |
| **语音输入** | 一个念头就是指令 | 自然交互 |
| **多频道桥接** | 接 Telegram/元宝/钉钉/飞书 | 生态兼容 |

### 可以后有（Day 30）

| 功能 | 说明 |
|------|------|
| **App 生态** | 任何人可创建 Skill/App |
| **分身广场** | 公开的 Agent 分身市场 |
| **记忆可视化** | 看到 Agent 的记忆图谱 |

## 三、技术选型

### 前端

| 方案 | 优势 | 劣势 | 推荐 |
|------|------|------|------|
| **Web App** | 跨平台、无需安装 | 体验一般 | ✅ 先做 |
| **微信小程序** | 国内用户覆盖最广 | 审核严格、限制多 | ⚠️ 第二步 |
| **桌面客户端** | 体验最好 | 开发成本高 | ❌ 不急 |
| **移动 App** | 随身携带 | 开发成本最高 | ❌ 远期 |

**推荐路径：Web App → 微信小程序 → 移动 App**

### 后端

| 组件 | 选型 | 理由 |
|------|------|------|
| **通信协议** | WebSocket | 实时双向，国内无障碍 |
| **消息队列** | Redis Pub/Sub | 轻量，已有基础设施 |
| **持久化** | SQLite + WAL | Δ总线的统一存储 |
| **部署** | 自托管 VPS | 数据主权，不仰望于人 |

## 四、与外接平台的关系

```
           ┌─────────────────────────┐
           │      Isa（主入口）       │
           │   我们自己的频道客户端   │
           └────────────┬────────────┘
                        │
                   Δ总线（统一接入）
                        │
         ┌──────┬───────┼───────┬──────┐
         ▼      ▼       ▼       ▼      ▼
      Telegram 元宝   钉钉    飞书   微信
      (副入口) (副入口) (副入口) (副入口) (副入口)
```

- **Isa 是主入口**：身份、记忆、技能都在这里完整呈现
- **外接平台是副入口**：通过 Δ总线桥接，体验可能不完整但可用
- **不依赖任何一个外接平台**：任何一个断了，Isa 照常运行

## 五、乔布斯设计原则

| 原则 | 在 Isa 中的体现 |
|------|-----------------|
| **触摸即响应** | 打开网页就能聊，不需要注册/配置 |
| **永远在身边** | 浏览器标签常驻，通知推送 |
| **一个入口，无限可能** | 聊天、分身、技能、记忆，都在一个界面 |
| **好看** | 简洁、温暖、有设计感 |
| **好用** | 三步之内完成任何操作 |
| **好造** | 最小技术栈，一个人能维护 |

## 六、最小可行路线图

```
Week 1: 原型
  ├── Web 前端（React/Vue + WebSocket）
  ├── 最简后端（Python/FastAPI + WebSocket）
  ├── DM 聊天功能
  └── 接入 Δ总线（JSON 消息格式）

Week 2: 核心
  ├── 群组功能
  ├── 分身管理（创建/切换/删除分身）
  ├── 国内部署（VPS + 域名）
  └── 接入 openLLM（消息 → 决策 → 响应）

Week 3: 增强
  ├── 状态可见（Agent 在想什么）
  ├── 语音输入（Web Speech API）
  ├── 多频道桥接（接 Telegram 兜底）
  └── 基础样式美化

Week 4: 生态
  ├── Skill 管理界面
  ├── 记忆查看界面
  └── 邀请机制（分享群组链接）
```
